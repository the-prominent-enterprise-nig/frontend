# Scenario 56 — Reports as Excel Files With In-Depth Pivot Tables — Gap Analysis & Closing Plan

**Source**: direct client ask, relayed 2026-09-21:

> "Client wants the reports pulled internally should be in excel files, in in-depth pivot tables"

A follow-up to Scenario 47 (_Client-Requested Reports & Excel Extraction_), which gave four reports an Excel export. This ask widens it on two axes: **every** internal report, and **pivot tables** — not a flat Detail sheet "for the user to pivot themselves", which is what Scenario 47 shipped.

## Related ClickUp Tickets

- [86d3958g5](https://app.clickup.com/t/86d3958g5) — **"BI & Reporting branch / management reports & exports configured"** — the umbrella ticket Scenario 47's doc cites for all report exports. Not re-checked for a pivot-specific child ticket this session; none was known.

## Decisions already taken (developer, 2026-09-21)

1. **"In-depth pivot tables" means real Excel PivotTables** — each `.xlsx` carries native, refreshable pivots the client can re-slice by dragging fields, not pre-summarised static sheets. Chosen over the simpler "fixed summary sheets" option, accepting that the pivot XML has to be hand-written (see Gap 1).
2. **Sequencing** — the four existing Scenario 47 exports first, then inventory reports + AP Aging, then every remaining report ("finish all reporting then we move on").
3. **Branching** — work on a fresh `feat/excel-pivot-reports` off `development` in both repos, not on top of the in-flight Scenario 54 branch.
4. **Local DB** — migrate the dev DB to `development`'s schema (`prisma migrate deploy`, never `reset`) so the exports could be exercised against real seeded data.

## The scenario we're building toward

An accountant or manager opens any report, sets its filters, clicks **Export to Excel**, and the file opens on **pivot sheets** — sales by branch × month, inventory value by warehouse × brand, AP owed by vendor × aging bucket, P&L by month and branch — that they can pivot further in Excel without rebuilding anything. Behind the pivots sit the same **Summary** (matches the screen), **Detail** (the rows the pivots read) and **Parameters** (filters, who, when) sheets Scenario 47 established.

## What's already done ✅

1. **The whole export pipeline exists** (Scenario 47 Part 1) — `backend/src/common/export/xlsx.util.ts` (`buildReportWorkbook()`, Summary/Detail/Parameters, 100k-row cap), `send-xlsx.util.ts`, `@AuditReportExport(slug)`, and on the frontend `downloadXlsx.ts` + `<ExportButton>`. The `/api/[...path]` proxy already streams binary. Every new export is "a JSON endpoint's sibling `/export` on the same service call", no new plumbing.
2. **Four reports already export** — Sales per Branch, Sales per Brand, AR Aging per Branch, Expenses per Branch.
3. **`exceljs` is already a backend dependency**, and `jszip` is already in the lockfile (as an `exceljs` dependency).

## What's not done / gaps ❌⚠️

1. **`exceljs` cannot write pivot tables.** 4.4.0 (the published version) has no pivot support at all; an experimental `addPivotTable` exists only on its unreleased master. No other JS library writes them either — the `PivotCacheDefinition` / `PivotCacheRecords` / `PivotTable` OOXML parts have to be generated by hand.
2. **No existing export has a pivot.** The only mention of "pivot" in either repo was the Scenario 47 comment describing Detail as what "someone pivots themselves".
3. **Twelve report screens have no Excel export at all** — Trial Balance, P&L, Balance Sheet, Cash Flow, AP Aging, GRNI, Cost Center, Customer Statement, General Ledger, and the three inventory reports.
4. **The inventory reports' "Export CSV" exports one page.** Valuation, Turnover and Aging each hand-roll a CSV from `data.data` — the current paginated page (20 rows), not the report.
5. **The financial statements carry no dimension to pivot by.** P&L / Balance Sheet / Cash Flow are account-balance lists — no month, no branch, no journal type. Pivoting them needs line-level data underneath.
6. **Inventory rows lack brand**, and turnover rows return `category: null` for every item — the two dimensions a retailer of branded appliances most wants to slice by.
7. **AP Aging's rows are thin** — bill no., vendor, dates, outstanding, bucket; nothing on status, amounts, withholding, cost center or expense account.

## Closing the gaps

### Part 1 — Native pivot writer (shared by every report)

- `backend/src/common/export/pivot.util.ts`: takes the buffer `exceljs` writes (with an empty placeholder sheet per pivot) and injects, per pivot, a cache definition (field list + sorted distinct values for axis fields), cache records, a pivot table definition (rows / columns / report filters / values), their relationships, content types, and the workbook's `<pivotCaches>`.
- Every cache is written `refreshOnLoad="1"`, so Excel rebuilds the pivot from the Detail sheet on open — the file only has to be structurally valid, not carry pre-rendered cells.
- `ReportWorkbookSpec` gains an optional `pivots: PivotSpec[]` — `{ name, sourceSheet, rows, columns?, filters?, values[{ key, fn, name, numFmt }], order? }`. `order` fixes an axis's item order where alphabetical is wrong (aging buckets, P&L sections). Pivot sheets go first so the file opens on the analysis.
- Safety rails: a pivot naming a column its sheet lacks throws; the TOTAL row is excluded from every pivot range; a report with **no rows** keeps the pivot sheet with a "nothing to pivot" note but gets **no pivot** (a pivot over a header-only range is one Excel can refuse the file over).

### Part 2 — Pivots on the four existing exports

- **Sales (branch / brand)**: Net Sales by Month · Profitability (units, net, cost, margin) · By Invoice Type — each led by the report's own grouping. Detail gains a `Month` column.
- **AR Aging**: Branch × Bucket (with collector) · Collector (accounts, outstanding, MI due, penalty) · Customer × Bucket, buckets in aging order.
- **Expenses**: Category × Branch · Month × Branch · Payee. Detail gains `Month`.

### Part 3 — Inventory reports + AP Aging

- **Backend**: `valuation/export`, `turnover/export`, `aging/export` on `inventory/reports`, each reusing its JSON report's service method unpaginated (limit = export cap + 1, so over-cap still 400s rather than truncating), plus one batched item lookup for brand/category (the costing valuation code is untouched). Filter names, not ids, on the Parameters sheet. `reports/aging/ap/export` with a vendor × bucket Summary.
- **AP aging rows** gain vendor code, reference, status, amounts, withholding, cost center, expense account — additive; the screen ignores them.
- **Frontend**: the three hand-rolled CSV buttons become `<ExportButton>` fed with the dashboard's own filters minus paging; AP Aging gets the hub's button.

### Part 4 — Every remaining report

- **Trial Balance** (type › category › account), **Balance Sheet** (section › category › account + an assets-vs-L+E difference line), **GRNI** (supplier × age, warehouse × month), **Cost Center** (cost center × source, by month — backed by a new record-level `costCenterDetail()`), **Customer Statement** (by month, plus a Payments sheet of payments and credit memos).
- **P&L, Cash Flow, General Ledger** get **journal-line Detail** (Gap 5): `generalLedger()` now also returns journal type, branch, source module and account type/category (additive), and takes optional `{ branchId, view }` so the P&L export's lines match the statement's own scoping. P&L pivots use a signed Net Income Effect, so the grand total _is_ net income rather than revenue and costs added together.
- **Frontend**: one `ExportButton` in the Reports hub filter bar driven by a `hubExport(tab)` map (Expenses keeps its own; BI Summary, AR Aging, GL Reconciliation get none), and one on the General Ledger page.

### Part 5 — Testing

- Unit specs round-tripping real `.xlsx` buffers (package-level, since `exceljs` can't read pivots back).
- Backend e2e across all 16 exports; Playwright for the buttons, downloads and filter pass-through.

## Not in scope for this doc

- **BI Summary** (four KPI tiles — nothing to pivot), **GL Reconciliation** and the **inventory Reconciliation** report (diagnostic exception checks, the latter capped at 50 samples).
- **Supplier Statement** — has a backend endpoint but no screen.
- **Operational screens** — collections, cash forecast, special-accounts ledger, collection incentives, cash-in-transit (still hand-rolled CSV). Only if the client counts these as "reports".
- **Streaming exports** — still a buffered workbook under the 100k-row cap from Scenario 47.

## Open questions

- **Does Excel keep the fixed item order on refresh?** Aging buckets, P&L sections and turnover statuses are written in business order with no `sortType`, which Excel is specified to respect. Apple Numbers re-sorts them alphabetically. Unverified in Excel. Fallback if it doesn't: prefix the labels ("1 · Current").
- **Do pivots over 1,000+ source rows load in Excel?** See Worth-flagging — Numbers refuses them; Excel has no such documented limit, but nobody has opened one in Excel yet.
- **Should the operational screens get exports too?** (See Not in scope.)

**Worth flagging:**

- **Not yet opened in Microsoft Excel.** Verification used Apple Numbers (no Excel/LibreOffice on this machine): it imports the pivots as real pivot tables and every total checked matched the source rows (e.g. sales profitability 450 units / ₱748,500 net / ₱523,950 cost / ₱224,550 margin; P&L net income ₱65,772 per branch and overall; AP ₱61,770 over 60 bills). **Someone with Excel needs to open one large export** (Inventory Aging) before this goes to the client.
- **Apple Numbers drops pivots whose source exceeds 1,000 rows** — exactly: 1,000 imports, 1,001 doesn't, also with the cached records stripped out. So on real data Inventory Valuation (1,108 rows) and Inventory Aging (14,514) open in Numbers as plain tables. Believed Numbers-only; this is the second reason the Excel check matters.
- **One real bug found and fixed by testing on real data**: the first cut injected a pivot even when a report had no rows — a pivot over a header-only range, which Excel can reject the whole file over. Now a note instead.
- **One test-authoring bug caught by flakiness**: the first run of the new backend e2e failed Balance Sheet once, then passed. The coverage table recorded Balance Sheet's row count _after_ later tests — the tell of a 5 s Jest timeout expiring while the request kept running. Fixed with a 30 s per-test budget; 3/3 clean runs after.
